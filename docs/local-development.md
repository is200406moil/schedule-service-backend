# Локальная разработка

Исходники сервера находятся в `backend/`, интерфейса — в `frontend/`.
Собранный интерфейс попадает в `frontend/dist/`; FastAPI раздаёт его по адресу
`/static/react/`. Содержимое `dist/` не нужно переносить в сервер или добавлять
в Git.

## Что установить

- Python 3.12 — та же версия, что в Docker и CI.
- Node.js 22 LTS, не ниже 22.12, с npm. Текущий Vite также допускает Node.js
  20.19 и новее в ветке 20, но Node.js 21 не подходит.
- Docker Compose, если PostgreSQL и сервис расписания будут запущены
  в контейнерах.

Команды ниже рассчитаны на PowerShell в Windows. Python, Node.js и Docker
нужно установить отдельно. Для создания окружения используется `python`
из `PATH`: проверьте его версию командой `python --version`.

## Подготовка

Откройте PowerShell в корне репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
npm ci --prefix frontend
npm run build --prefix frontend
```

Если корневое окружение `.venv` уже создано, пропустите первую команду.
Активация не требуется: команды обращаются к Python из этого окружения
напрямую. Проверяйте результат каждой команды; при ошибке сначала устраните
её, а затем продолжайте.

Python-зависимости сервера зафиксированы в `backend/requirements.txt`.
`backend/requirements-dev.txt` подключает тот же список и добавляет инструменты
проверки. Docker использует серверный список, локальная разработка и CI — список
для разработки. Версии npm-пакетов и их вложенных зависимостей сохраняются
в `frontend/package-lock.json`; `npm ci` устанавливает именно этот набор.

Скопируйте `.env.example` в корневой `.env` и заполните настройки. Приложение
читает этот файл независимо от рабочей папки. Реальные секреты и `.env`
не добавляйте в Git.

## Базы данных и расписание

Чтобы запустить только зависимости для локального сервера:

```powershell
docker compose up -d --build db schedule-db schedule-api
docker compose run --rm schedule-refresh
```

Используйте в `.env` локальные адреса из `.env.example`: PostgreSQL на
`localhost:15432`, API расписания на `localhost:5000`. В контейнере приложения
адреса другие — Compose задаёт их отдельно. `SCHEDULE_API_BASE_URL` относится
к локальному серверу, а `COMPOSE_SCHEDULE_API_BASE_URL` — к приложению в Docker.
Так копирование `.env.example` не направляет контейнер к его собственному
`localhost:5000` вместо сервиса расписания.

Первая загрузка расписания может занять несколько минут. Для проверок
контейнеры не нужны: тесты по умолчанию используют отдельную SQLite-базу
в памяти. Не задавайте `TEST_DATABASE_URL` равным рабочей базе: тесты создают
и удаляют таблицы в указанной тестовой базе.

## Проверки

Из корня репозитория:

```powershell
cd backend
..\.venv\Scripts\python.exe -m pip check
..\.venv\Scripts\python.exe -m ruff check .
..\.venv\Scripts\python.exe -m ruff format --check app tests
..\.venv\Scripts\python.exe -m pytest --cov=app --cov-branch --cov-report=term-missing --cov-fail-under=80
cd ..
npm run lint --prefix frontend
npm run build --prefix frontend
npm test --prefix frontend
```

Эти команды проверяют зависимости, код и форматирование сервера, покрытие
строк и ветвлений не ниже 80%, линтер интерфейса, сборку и клиентские тесты.
После изменения зависимостей повторите их установку из раздела «Подготовка».

`npm run lint` использует закреплённый Oxlint и явный набор правил в
`frontend/.oxlintrc.json`: обычные ошибки JavaScript/TypeScript, ключи JSX,
повторяющиеся свойства и правила хуков React, включая зависимости эффектов.
Проверяются исходники, тесты и конфиг Vite; предупреждения завершают команду
с ошибкой. Это базовая проверка кода, а не весь набор оптимизаций React Compiler
или замена отдельному проходу React Doctor. React Compiler в сборке не подключён.

## Запуск приложения

Из корня репозитория перейдите в `backend`, примените миграции, затем запустите
сервер. Миграции изменяют базу из `DATABASE_URL`, поэтому проверьте её адрес
заранее. Не запускайте сервер, если миграции завершились с ошибкой.

```powershell
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000/ui/login> в браузере.
Остановить сервер можно сочетанием `Ctrl+C`; вернуться в корень — `cd ..`.
В Docker миграции автоматически применяет `backend/prestart.sh` перед
запуском сервера.

Для автоматической перезагрузки Python-кода или другого порта:

```powershell
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765 --reload
```

Эту команду тоже выполняйте из `backend`.

## Работа над интерфейсом

В отдельном PowerShell из корня репозитория запустите:

```powershell
npm run dev --prefix frontend
```

Команда наблюдает за исходниками React и автоматически пересобирает их в
`frontend/dist`. Дождитесь сообщения об успешной сборке, затем обновите
страницу приложения в браузере. Адрес остаётся адресом FastAPI, например
<http://127.0.0.1:8765/ui/login>. Отдельный Vite-сервер и настройка CORS не нужны.
Это автопересборка, а не HMR: открытая страница сама не обновляется, а
несохранённый черновик при ручной перезагрузке может быть потерян.
После изменения `vite.config.ts` перезапустите команду наблюдения.

Для разовой сборки используйте `npm run build --prefix frontend`.
Перед коммитом выполните линтер, полную сборку с проверкой типов и тесты из
раздела «Проверки». Режим наблюдения не заменяет эти проверки.
Остановить наблюдение можно через `Ctrl+C`. Для обычного запуска уже
собранного приложения Node.js не требуется.
