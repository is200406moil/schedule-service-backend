## Что изменено

| Область | Изменение | Чем проверено |
| --- | --- | --- |
| Вход и регистрация | Поля и сообщения вынесены из сложного компонента. Сохранены обычная отправка формы, CSRF и автозаполнение. | Переключение видимости пароля без потери значения, отправка полей и CSRF, восстановление после `pageshow`, фокус на ошибке. |
| Редактор задачи | Загрузка данных, состояние формы и сообщения разделены. Повторная отправка блокируется сразу; после ошибки можно повторить запрос, после успеха форма остаётся заблокированной до перехода. | Валидация, отмена загрузки, независимые запросы, смена задачи, повторный клик, ответы 401/403/404/422, сохранение неизменённого срока. |
| День календаря | Занятия и задачи вынесены в самостоятельные компоненты. | Прежняя и новая статическая разметка совпала в 128 сочетаниях состояний. |
| Строки занятий | Ключи строятся по содержимому занятия, а не его позиции. Одинаковые строки получают разные суффиксы. | Перестановка, вставка, одинаковые названия и время при разных остальных данных, полные дубликаты. |
| Даты и время | Постоянные форматтеры переиспользуются. Для меняющихся параметров есть кеш максимум на 32 записи. | Московское время и граница суток, одинаковые параметры в разном порядке, подсчёт созданий форматтера, вытеснение старых записей. |
| Удаление задачи | Закрытие через `cancel` и кнопку запрещено во время запроса. Завершение операции не влияет на окно другой задачи или закрытый компонент. | Событие `cancel`, быстрые повторные клики, ошибка и повтор, устаревшие ответы, размонтирование и Strict Mode. |
| Создание задачи | Очистка эффекта закрывает захваченный узел окна, а не читает изменяемый `ref`. | Размонтирование закрывает исходное окно и восстанавливает прокрутку страницы. |
| Профиль | Форма зависит от пяти редактируемых полей, а не всего объекта профиля. | Смена фото не стирает черновик; изменение сохранённых данных и отмена обновляют поля. |
| Подписи и навигация | Для срока добавлена явная связь через `aria-labelledby`; общий компонент убрал дублирование разметки навигации. | Связи подписей и полей с разными префиксами, существующие проверки оболочки. |
| Выбранная дата обзора | Начальная дата задаётся лениво; после этого выбор принадлежит пользователю. | Новый объект начальных данных не сбрасывает выбор; кнопка «Сегодня» продолжает работать. |

API расписания не предоставляет идентификаторы отдельных занятий. Ключи
различимых строк теперь устойчивы к перестановке, но индивидуальную
идентичность совершенно одинаковых записей восстановить из таких данных
нельзя. Если у строк появится собственное редактируемое состояние, понадобятся
идентификаторы со стороны API.

## Оставшиеся предупреждения

Пути указаны относительно `frontend/src/`.

| Место и правило | Почему рекомендация неприменима |
| --- | --- |
| `features/tasks/TaskDeleteDialog.tsx:49`, `no-loading-flag-reset-outside-finally` | Сброс уже находится внутри `finally` и выполняется только для текущей операции. Анализатор не распознаёт такую защиту при сбросе идентификатора операции также в cleanup. Удаление защиты ради предупреждения вернёт обработку устаревших ответов. Правило проверено на исходнике и его вариантах в памяти; сценарии покрыты тестами. |
| `features/tasks/useTaskEditorForm.ts:82`, `no-loading-flag-reset-outside-finally` | Сброс находится в `finally` под условием неуспешного сохранения. После успеха форма намеренно остаётся заблокированной до перехода, чтобы не создать дубликат. Тесты проверяют повтор после ошибки и блокировку после успеха. |
| `shared/dates.ts:26`, `js-hoist-intl` | Конструктор вызывается только при отсутствии нужных параметров в ограниченном кеше. Один постоянный форматтер не подходит для разных параметров. Тесты считают реальные вызовы конструктора и проверяют границу кеша. |
| `features/tasks/taskEditorModel.ts:81`, `js-set-map-lookups` | Это `string.includes` для поиска подстроки, а не поиск элемента массива. `Set.has` изменит поведение и сломает частичный поиск предметов. Частичный поиск и нормализация проверены тестами. |

## Как повторить анализ

Ссылка пользователя ведёт на
[форк React Doctor](https://github.com/ahmedkhaleel2004/react-doctor).
Команда из его README устанавливает npm-пакет проекта
[millionco/react-doctor](https://github.com/millionco/react-doctor).
Оба прохода выполнены опубликованной версией `0.9.14`, а не плавающим
`latest`. Локальная версия Node.js — `22.19.0`.

Из папки `frontend`:

```powershell
$env:REACT_DOCTOR_NO_TELEMETRY = '1'
npx.cmd --yes react-doctor@0.9.14 . --scope full --no-telemetry --no-supply-chain --no-cache --yes --blocking none --json
```

Фактический запуск использовал тот же CLI из отдельной временной установки.
Итоговый JSON содержит `complete: true`, 76 проанализированных файлов и пустой
список `skippedChecks`. Все шесть точек входа Vite попали в анализ.

Результаты сохранены локально, функции телеметрии и публикации отчёта не
использовались. Внешняя проверка зависимостей Socket.dev отключена и в результат
не входит; проверка npm-зависимостей выполнена отдельно. Сам анализатор и его
зависимости загружались через npm.

Числовой балл не получали: `--no-telemetry` отключает также внешний сервис
подсчёта балла. `--blocking none` не означает отсутствие проблем — нужно
смотреть счётчики, диагностику и полноту прохода, а не только код выхода.

считается одобренным по результатам тестов.

Почтовой верификации и восстановления пароля пока нет; это следующий
отдельный этап. Нулевое число ошибок React Doctor не подтверждает безопасность
будущих почтовых сценариев или готовность сервиса к публичному запуску.

Полный повтор React Doctor после этих изменений дал тот же результат:

Все 132 клиентских и 110 серверных тестов снова прошли. Обновлённый Docker-образ

Для постоянной проверки добавлен `oxlint@1.85.0` в зависимости разработки.
Его политика — 25 явно выбранных проверок обычных ошибок JavaScript/TypeScript,
JSX и хуков React. Правила проверены также на ошибочных примерах: условном

При пробном включении всего набора React Compiler анализатор дополнительно

## Проверка авторизации в браузере — 3 октября

Браузерное соединение восстановлено. Вход и регистрация проверены на отдельной
новой тестовой базе: 1280×900, 375×812, 320×740 и 812×375. Проверены ошибки,
успешный вход, работа с клавиатурой, показ пароля и уведомление cookies.
Подробности и ограничения этого прохода — в [плане интерфейса](ui-redesign-plan.md).
Проверка физической экранной клавиатуры и системного увеличения текста ещё
не выполнена; остальные страницы этим проходом не проверялись.

Исправлены несовпадения между HTML-ограничениями и сервером: длина пароля
считается по кодовым точкам Unicode, а поле почты не блокирует адреса,
которые принимает сервер. Проверка пароля читает текущее значение поля
при отправке, включая автозаполнение; сам пароль не хранится в состоянии React.
Добавлены клиентские и серверные регрессионные тесты этих случаев.

После исправлений проходят 150 клиентских и 124 серверных теста, сборка,
TypeScript и линтер. Покрытие сервера с ветвлениями — 88,79%. Полный повтор
React Doctor 0.9.14: 76 файлов, 0 ошибок, прежние 4 предупреждения,
`complete: true`, `skippedChecks: []`, `score: null`. Новых замечаний
по авторизации нет. Расширенные замечания Compiler, описанные выше,
этим этапом не исправлялись. Docker-образ после этих двух изменений
ещё не пересобирался.

## Восстановление пароля — 3 октября

Добавлены формы запроса письма и нового пароля в `features/auth`, без новых
зависимостей выполнения. Пароль остаётся в поле DOM, проверка читает актуальное
значение при отправке, включая автозаполнение. Токен принимается только из
строго проверенного fragment. Ссылки ошибок и переход к содержимому меняют
фокус, но не fragment, чтобы не потерять одноразовую ссылку.

Клиентские проверки охватывают подтверждение пароля, кодовые точки Unicode,
повторную отправку, возврат `pageshow`, отсутствие и смену fragment, серверную
ошибку, фокус и честные сообщения при выключенной или локальной почте.
195 тестов в 25 файлах, TypeScript, линтер и production-сборка прошли.

Полный проход React Doctor 0.9.14: 84 файла, 0 ошибок, прежние 4 предупреждения,
`complete: true`, `skippedChecks: []`, `score: null`. По восстановлению новых
диагностик нет. Телеметрия и внешний подсчёт балла не включались.

219 серверных тестов прошли на отдельном PostgreSQL, включая два сценария

## Подтверждение почты — 3 октября

Добавлены `VerificationPage`, форма запроса и форма явного подтверждения.
Существующие публичные классы и шрифт сохранены. Строго проверенный токен
из fragment читается при первом отображении и повторно при отправке; сам GET
не отправляет POST. При возврате `pageshow` кнопка снова доступна. Пропуск
навигации и ссылки ошибок перемещают фокус без подмены fragment.

После регистрации и повторного запроса экран сначала предлагает открыть письмо.
Форма подписана как повторная отправка. Локальный режим описывает тестовый файл,
не настоящую доставку. Выключение отправителя запрещает новые письма, но не
мешает явно подтвердить уже выданную ссылку. Блоки страницы разделены на
компоненты; новую проверку сложности React Doctor удалось пройти без исключений.

`skippedChecks: []`, `score: null`. Телеметрия не включалась. Расширенные

переполнения нет; фокус прокручивает кнопку в видимую область короткого экрана.
Физическая экранная клавиатура и системное увеличение текста пока не проверены.
